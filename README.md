# Whatcha · 在干嘛

One iPhone screen for a parent to ask 小乐, their child's AI agent, what the child is doing. M1 ports the Android WeChat-style text conversation to SwiftUI, iOS 17+, through the public relay. No menus or settings.

Open `Whatcha.xcodeproj`. Copy `Config.example.xcconfig` to `Config.xcconfig` and fill in `AGENT_ADDRESS` and `INVITE_CODE` before building. That file is ignored by Git. Pairing is compiled into Info.plist; the parent configures nothing. Without an address the app shows the Android unpaired instructions. The phone creates its own Ed25519 identity in Keychain on first launch.

Simulator only, no signing team or device distribution:

```sh
xcodebuild -scheme Whatcha -destination 'platform=iOS Simulator,name=iPhone 15' -derivedDataPath build test
```

While no runtime is available:

```sh
xcodebuild -scheme Whatcha -destination 'generic/platform=iOS Simulator' -derivedDataPath build build
xcodebuild -scheme Whatcha -destination 'generic/platform=iOS Simulator' -derivedDataPath build build-for-testing
swift test --disable-sandbox --scratch-path build/swiftpm
```

The native macOS XCTest run exercises the same `Sources/WhatchaCore` and test files as the iOS test target. It does not verify the iOS screen, Keychain, or live relay. Build products and logs belong under the ignored `build/` directory. See [PLAN.md](PLAN.md) for Round 1 results and remaining acceptance checks.

The app keeps its lines, delivery states, title and session in one atomically written file. A pending message survives reopening. On reconnect, a completed answer in the host's `chat_items` is shown instead of asking again; a running turn is left alone. Questions go out one at a time. A grey circle means on its way; tapping a red ! retries that failed line. Connection retries wait 5, 10, 20, 40, 60 seconds, with a 10-second CONNECT deadline and an early retry when the app returns to the foreground.

M1 deliberately has text only. Voice, photos, read aloud, QR pairing and push are later work. The empty hint says 「打字就行」 so it describes what this build supports.

The signature fixture was generated by `tools/AndroidWireVector.java` against the Android reference's compiled `Wire` and `Identity` classes, using the public test seed `00…1f`. `python3 tools/generate-vector.py` regenerates it after the Android debug build. The tests compare exact canonical payloads and verify both Android's fixture signatures and CryptoKit's generated signatures. CryptoKit randomizes Ed25519 signatures, so their bytes differ from Android's deterministic output; see [Apple's signature documentation](https://developer.apple.com/documentation/cryptokit/curve25519/signing/privatekey/signature(for:)). `tools/SwiftWireVector.swift` supports the reverse check with Android's canonicalizer and Bouncy Castle verifier. These tools never use an installed app or agent identity.

The owner runs the test agent named in PLAN.md. On an iPhone 15 simulator: type 「在干嘛」, tap 发送, and check the Chinese answer, avatars, tails and title; then queue two questions offline, return to the app, retry a failure, and reopen after a completed answer. Verify only one INPUT for the recovered question in the host log. Check long answers, the keyboard, scrolling and large text separately. These checks are still required before M1 is accepted.
